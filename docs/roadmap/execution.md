# EXE — Agents, tools, containers and gateway

**Scope:** `agent.py`, `session.py`, `pi_adapter.py`, `pi_container.py`, `gateway.py`, `gateway_runtime.py`, `environment.py`, `docker/pi-kali/`. Pi runs within Kali Rolling containers with long-lived RPC where configured.

### EXE-01 [~] P0 — Execution trust boundary
Deliver: documented threat model and enforceable mounts, secret isolation, rootfs permissions, capability/PID/CPU/RAM limits, network rules, non-privileged default and artifact handoff. Agent must not access authoritative World DB, verifier or benchmark credentials.
Accept: integration tests attempt to mutate protected state, obtain secrets, escape allowed workspace and contact denied destinations; failures are observable.

Current implementation isolates each run's writable `agent-workspace/` from the Harness-owned run root. Local and benchmark runners pass only that workspace to Agent adapters and verifiers; World DB/events, result, progress ledger, trace, checkpoints, evidence, and verifier logs remain in the parent run directory. Container Agents run with the workspace owner's numeric UID/GID; when Harness runs as root, it prepares the workspace for UID/GID 65532. Harness refreshes context/progress atomically with readable permissions for that identity. Agent event, world, submission, and telemetry files are treated as untrusted regular files and opened without following symlinks; Gateway reads and writes traverse workspace paths without following symlinks. See [the execution threat model](../security/execution-boundary.md). Tests cover workspace separation and symlink replacement, protected-path Gateway writes, Docker/Pi mount configuration and non-root identity, and a container integration probe for hidden World state, host secrets, non-root execution, read-only root, and denied loopback egress. Local validation on 2026-10-09: full suite 235 passed, 2 Docker tests skipped because Docker is unavailable; Ruff, architecture test, compileall, and diff checks passed. Both the isolation probe and fake Pi resume integration are wired into CI after building their images; neither ran in this local environment. Maintainer review is required before merge because this changes the Agent-visible workspace contract and execution trust boundary.

Strict network-profile Agent containers now explicitly blank Docker CLI proxy defaults (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `FTP_PROXY`, `ALL_PROXY` and lowercase variants) and reject Agent-configured proxy env/passthrough. This closes a path where a Docker client proxy URL, possibly containing credentials, could enter the Agent environment or let a model-allowed Agent bypass its Gateway. Command tests cover Docker/Pi clearing and explicit proxy rejection; the Docker boundary probe configures proxy canaries and checks the Agent cannot read them. Focused boundary tests passed (26 passed, 1 Docker integration skipped); full suite passed (462 passed, 4 Docker-dependent skips), Ruff, compileall and `git diff --check` passed on 2026-10-09. Local Docker is unavailable, so the actual injected-proxy container test remains for CI. Maintainer review remains required for this trust-boundary change.

Pi now defaults to no added Linux capabilities; `NET_RAW` and any other capability must be explicitly listed in `pi.cap_add`. Command-contract tests now assert both Docker and Pi Agent launch commands enforce read-only root filesystems, drop all capabilities, disable privilege escalation, and apply explicit PID, memory, CPU, and tmpfs limits. Tests also verify the no-capability default and explicit opt-in command. This aligns the default container with the dropped-capability boundary; Docker integration evidence and maintainer review remain outstanding.

Corrected the Pi image README, which had incorrectly claimed `NET_RAW` was enabled by default; it now documents the empty default capability set and explicit `cap_add` opt-in. Pi command/config and image contract tests passed (3). This documentation fix does not replace the pending Docker isolation probe or maintainer review.

Closed a task-mount leak found during boundary review: container Agents previously mounted the complete task directory, which could expose the Python verifier source. Docker and Pi now mount a stable read-only task-input snapshot that omits the configured verifier and skips symlinks. The snapshot is capped at 4,096 files/2 GiB, excludes any nested run root, rejects task roots inside authoritative run storage, and is content-checked when reused for recovery. The isolation probe now verifies `/task/verifier.py` is absent; unit tests verify safe-copy behavior, symlink exclusion, changed-input rejection, and Docker/Pi mount selection. Validation on 2026-10-09: full suite passed (320 passed, 3 skipped), Ruff, compileall, architecture test and `git diff --check` passed. The Docker isolation probe is wired into CI but remains unrun locally because Docker is unavailable; maintainer review remains required for this trust-boundary change.

Container Agent schemas and launch boundaries now reject host environment passthrough for token-named variables and reserved Harness, benchmark, or TSec credential names. Explicit provider API keys such as `OPENAI_API_KEY` remain available for direct-provider mode. Runtime launch checks repeat the validation so mutated `AgentSpec` objects cannot bypass load-time validation. Tests cover Docker/Pi env config, Pi passthrough, mutated specs and allowed provider keys. Validation on 2026-10-09: full suite passed (334 passed, 3 skipped), Ruff, compileall, architecture test (1 passed) and `git diff --check` passed. The Docker isolation probe and maintainer review remain outstanding.

Task snapshot review found that excluding the verifier by filename still allowed a hard-link alias to copy its contents into the Agent-visible tree. Snapshot creation now rejects hard-linked regular files and opens each source through a no-follow path walk, including during the copy, preventing verifier aliases and parent-directory symlink races from being followed. The regression failed before the fix and passes after it. Workspace and container-boundary tests passed (6 passed, 1 Docker test skipped); full suite passed (376 passed, 4 skipped). Docker isolation CI evidence and maintainer review remain outstanding.

Verifier path review found that a symlinked verifier was skipped while its in-tree target was still copied into the Agent snapshot. Preflight validation and snapshot creation now reject a verifier entrypoint containing a symlink in any path component before creating the view. Regressions for final-component and parent-directory symlinks failed before the change; workspace and preflight tests pass (24). Full-suite and CI boundary evidence remain outstanding.

An end-to-end boundary review found that Container/Pi Gateway runtimes still received the original task directory even though the Agent container mounted the verifier-free snapshot. Since `file.read` is an authorized Gateway tool by default, this bypassed the task mount restriction. Orchestrator now passes the Agent-visible snapshot to Gateway for Docker/Pi runs, while the explicitly opted-in host CLI path retains the original directory. An Orchestrator-to-Gateway regression confirms an attempt to read the original verifier is denied (403). Gateway/task snapshot tests passed (26); full suite passed (384 passed, 4 skipped). Docker-backed confirmation of the sidecar mount remains outstanding.

### EXE-02 [~] P1 — Adapter/session contract and resource budget
Deliver: normalized event IDs, settled/terminal semantics, tool-call correlation and per-run token/tool/wall-clock/cost accounting; avoid double charging through gateway and Pi simultaneously.
Accept: fake Pi and real Docker smoke tests cover malformed RPC stream, settle/retry, cancellation, model errors, gateway disconnect and budget exhaustion.

Adapter/session event identities, settle/re-prompt semantics, tool-call correlation, cancellation and gateway/Pi accounting paths have regression coverage. Hardened budget ingestion so malformed or negative Agent-reported counters cannot crash the supervisor or reduce already charged usage: the run stops with `invalid_telemetry` and records a Harness telemetry/budget event. Pi RPC preserves raw usage values for the same fail-closed validation instead of coercing malformed data. Added tests for invalid strings, negative token/tool counters and malformed Pi usage. Focused adapter/session/budget tests passed (26); full suite passed (243 passed, 2 Docker tests skipped locally), Ruff, compileall and diff checks passed. The real Docker smoke and live Gateway disconnect checks remain before acceptance.

The compatibility `OneShotAgentSession` now applies the same strict counter/cost checks before updating checkpoint-visible live metrics. Malformed strings, booleans, negative counters and non-finite costs leave the snapshot unchanged and set an explicit `usage_telemetry_valid` flag; the adapter's BudgetMonitor remains responsible for stopping the process and recording `invalid_telemetry`. Parameterized regression coverage added. Validation on 2026-10-09: full suite passed (318 passed, 3 skipped), Ruff, compileall, architecture test, and `git diff --check` passed. Docker smoke and live Gateway disconnect acceptance remain open.

Hardened model Gateway disconnect handling. Connect/read errors before response headers now return a generic 502 body and record only the exception class; mid-stream disconnects send a generic SSE error, mark `model.response.complete=false`, emit the existing usage-missing event, and close the upstream response/client. Tests cover streamed and non-streamed connect errors plus disconnect after streaming begins, and assert provider error text/credentials do not leak. Focused Gateway tests passed (13). Validation on 2026-10-09: full suite passed (359 passed, 3 skipped); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Real Docker Pi-to-Gateway disconnect and budget-exhaustion smoke remain open.

Pi RPC command failures now persist only a generic message and the error value's type; the peer-supplied command ID is hashed for correlation, and the raw error body is discarded. The fake RPC regression covers a malformed record followed by an error containing a credential-like string and confirms it is absent from both session events and trace. Focused Pi adapter tests passed (15). Latest full validation on 2026-10-09: 359 passed, 3 skipped; Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker Pi smoke remains outstanding.

Added a fake Pi RPC budget-exhaustion acceptance test: usage above `max_tokens` stops the stream before a following `agent_settled` record, kills the named container, and returns `budget_exceeded=max_tokens` with the charged usage preserved. Focused Pi adapter tests passed (16); full suite passed (360 passed, 3 skipped). Docker Pi-to-Gateway disconnect and live container budget smoke remain outstanding.

Expanded the fake Pi RPC budget test across `max_tokens`, `max_model_calls`, `max_tool_calls`, and `max_cost_usd`. Each case checks that the over-limit usage is retained, the container is killed, and a later settled record is not consumed. For call budgets, the event that takes usage above the limit is already reported by Pi and is charged before the supervisor can stop it; the test makes no claim that the in-flight call can be prevented. Focused Pi adapter tests passed (19). Docker Pi-to-Gateway disconnect and live container budget smoke remain outstanding.

Closed the Pi RPC/Gateway accounting gap: Gateway model request/usage records are written to a Harness-owned event file outside the Agent workspace and mounted only into the Gateway sidecar. Pi RPC tails that trusted file, accounts Gateway model calls once, enforces budgets while the RPC process is running, and checkpoints a byte cursor so resumed sessions do not double charge. Public workspace events remain untrusted and are not used for this accounting path. Regression tests cover protected-vs-forged events, token/cost totals, budget exhaustion and cursor persistence. Focused Gateway/Pi/checkpoint tests passed (68); full suite passed (374 passed, 4 skipped); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Docker is unavailable locally, so real Pi-to-Gateway container smoke and disconnect acceptance remain open.

Recovery now fails closed if the trusted Gateway log disappears after a nonzero byte cursor was checkpointed; previously that condition could silently undercount usage. A regression covers the missing-log/cursor mismatch. Focused Gateway/Pi/checkpoint tests passed (67); full suite passed (375 passed, 4 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Docker integration acceptance remains open.

Budget monitoring now reads workspace telemetry as bytes and pins the event file's device/inode after its first read. If an Agent truncates or replaces the file after usage was charged, the monitor fails closed with `invalid_telemetry` rather than silently skipping the new contents at a stale cursor. Regressions cover both truncate and atomic-replace attempts. Focused budget/session/Pi tests passed (40); full suite passed (426 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Docker Pi-to-Gateway disconnect and live budget smoke remain outstanding.

Hardened the same telemetry path against memory exhaustion: monitor reads at most 1 MiB per poll, refuses files above 64 MiB and individual JSONL records above 4 MiB, and streams split records across polls without losing cursor correctness. Tests cover oversized files, oversized unterminated records and multi-poll parsing. Budget tests passed (9); full suite passed (432 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Live Docker Pi/Gateway budget smoke remains open.

Budget telemetry parsing now fails closed on syntactically invalid JSON, non-finite JSON constants, non-object events, missing/invalid event types, and non-object `data`. Previously these records were only logged and ignored, which could let malformed usage records bypass budget accounting. Valid usage read before the malformed record remains charged. Missing, symlinked, or otherwise unopenable telemetry files also fail closed; a real local subprocess regression confirms the supervisor terminates an Agent that swaps its telemetry file for a symlink. Regressions first reproduced the parsing gap (3 failures) and file replacement gap (2 failures), then passed; full suite passed (459 passed, 4 Docker-dependent skips), Ruff, compileall and `git diff --check` passed on 2026-10-09. Live Docker Pi/Gateway budget smoke remains open.

Budget telemetry now rejects a reported `total_tokens` smaller than the sum of input and output tokens in local Agent, one-shot session and Pi RPC accounting. Gateway usage normalization charges at least that sum for inconsistent upstream totals. Before the fix, a validly typed record with 6 input, 5 output and total 1 bypassed a five-token limit; regressions now prove local/Pi telemetry fails closed and Gateway usage is normalized to 11. Budget/session/Pi/Gateway tests passed (72), Ruff passed. Live container budget smoke remains open.

Pi RPC now fails closed when the protected Gateway accounting log records `model.usage_missing`; it no longer treats a request without token/cost data as zero usage. Gateway upstream token parsing rejects booleans, negative counts, fractional counts and malformed totals instead of coercing them with `int()`, and writes a missing-usage event so the Agent-side budget boundary stops. Regressions cover invalid upstream counters, the safe missing-usage event and Pi's refusal. Gateway tests passed (24); Ruff passed. Live Pi/Gateway container smoke remains outstanding.

Pi `message_end` records without a usage object now emit `model.usage_missing`, and both the Pi RPC budget monitor and generic one-shot telemetry path fail closed on that event. Previously a completed model response with no usage object could be treated as zero token/cost use. Regressions exercise Pi normalization, Pi RPC accounting, BudgetMonitor and OneShotAgentSession. Focused budget/session/Pi/Gateway tests passed (82); Ruff passed. Live container smoke remains open.

Added a non-Docker Pi RPC regression for routed model accounting: when a sidecar Gateway is configured, normalized Pi `message_end` usage is suppressed and the trusted Gateway `model.request`/`model.usage` events contribute the call, token and cost totals exactly once. The test covers both sides of the accounting boundary; it passed, and the full suite passed (498 passed, 4 skipped) with Ruff, compileall and `git diff --check` on 2026-10-09. Docker Pi-to-Gateway disconnect and live budget smoke remain outstanding.

### EXE-03 [~] P1 — Offline profiles and deterministic build
Deliver: separate `target-only`, `model-allowed` and `fully-offline` networking; pin image dependencies, pre-install binaries and reference data; no package installation required while solving.
Accept: no-public-egress smoke suite in a clean runner, plus network policy tests and documented model endpoint choices.

Added explicit `target-only`, `model-allowed` and `fully-offline` profiles while retaining `offline` and `benchmark-only` as compatibility names. Strict profiles reject host CLI Agents. `target-only` selects the task network only after Docker reports `Internal=true`; `model-allowed` requires a Docker Agent, sidecar Gateway, and an internal task network when one is configured, and attaches the Agent to the internal Gateway network; `fully-offline` selects Docker `none`. Preflight describes the required topology, and result projection identifies the enforced mode. Network policy tests cover internal-network rejection, missing Gateway, host-agent refusal, offline behavior, Docker adapter routing, and a Docker egress probe for internal networks. The Pi image now pins Kali's last-release OCI index digest, pins the Pi package version, pre-installs tools, and has a CI build step. Local full-suite validation on 2026-10-09: 283 passed, 2 Docker-dependent tests skipped; Ruff, compileall, architecture check, and diff checks passed. Docker-specific public-egress smoke and reproducibility across apt snapshot rollover still require clean-runner CI evidence; no completion claim is made.

`model-allowed` verifies that both the task network and Agent-facing Gateway network report Docker `Internal=true`; a public Gateway network is rejected. Strict network validation captures each inspected 64-character Docker network ID and uses it for Agent container creation and for attaching the checked target network. This prevents a network name from being removed and rebound to a public network between inspection and use. Regressions cover public Gateway rejection, malformed inspect output, Docker Agent commands using the checked Gateway and target IDs, and Pi RPC/JSON runners using the checked target ID. Network policy and Pi adapter tests passed (36). The full suite passed (502 passed, 4 Docker-dependent skips); Ruff, compileall, and `git diff --check` passed on 2026-10-09. The full suite ran with the temporary Python 3.11 environment on `PATH` so CLI fixtures could resolve their `python` command. Docker egress integration and clean-runner image reproducibility remain unverified.

The offline preflight now also validates the exact bounded task-tree constraints used by the container Agent snapshot, so hard-linked or oversized/unreadable task inputs are rejected before run allocation. Focused preflight/workspace tests passed (17); full suite passed (429 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. This improves early diagnostics but does not replace Docker target-network/public-egress or clean-runner image reproducibility evidence.

The Pi image now rewrites any `kali-rolling` APT source to `kali-last-snapshot` before package installation, while keeping the base OCI digest and Pi package version pinned. The static image contract test passed (1). Kali refreshes the last-snapshot branch with point releases, so this narrows package drift but is not a permanent per-package lock; the Docker image build and clean-runner rebuild comparison remain unverified locally because Docker is unavailable. See the [Kali repository branch documentation](https://www.kali.org/docs/general-use/kali-linux-sources-list-repositories/).

### EXE-04 [x] P2 — Tool execution capabilities
Deliver: domain-agnostic ToolAdapter with structured execution metadata, cancellation and evidence refs, selective domain plugins; maintain approval/authorization boundaries.
Accept: contract tests across filesystem, local process and authorized network tools; outputs remain untrusted.

Introduced `ToolAdapter`, `ToolExecutionContext`, and `ToolExecutionResult` as a domain-neutral asynchronous plugin contract. Gateway adapters must be explicitly registered, and the existing tool allowlist still controls authorization; shell/process and network tools remain unavailable unless a caller both injects an adapter and enables its tool name. Registered tools require a call ID; the Gateway seeds a fail-closed deduplication registry from the durable event log and returns 409 for an ID already observed, including after Gateway restart. Results include execution status, bounded JSON output, duration, sanitized adapter metadata and immutable content-hash references explicitly marked `untrusted`. Cancellation is signaled to adapters before the coroutine is stopped; interrupted executions are recorded as unknown. Gateway filesystem tools also return untrusted output hashes. Tests cover filesystem path constraints, an explicitly allowed network-shaped plugin, denied process-shaped tools, output provenance, cancellation signaling, and replay refusal after restart. The contract now has concrete plugins: `SandboxedProcessToolAdapter` runs an argv in a no-network bubblewrap namespace with resource and output limits, while `AuthorizedHTTPToolAdapter` restricts literal-IP requests by CIDR, port, method, redirect policy and response size. Gateway authorization remains an independent requirement for both. Validation on 2026-10-09: `tests/test_tool_plugins.py` passed (10, no skips), including live sandbox isolation, timeout, output and cancellation checks; the broader focused Gateway/ACI/action-verifier set passed (29); full suite passed (339 passed, 3 skipped); Ruff, compileall, architecture test (1 passed), and `git diff --check` passed. Acceptance criteria are met by the [tool plugin tests](../../tests/test_tool_plugins.py), [Gateway tests](../../tests/test_gateway.py), and [adapter tests](../../tests/test_tool_adapter.py). Maintainer review is required before merging this public execution extension point.

Added optional concrete implementations for both missing plugin types. `SandboxedProcessToolAdapter` executes argument arrays with bubblewrap's private network/PID namespace, no capabilities, read-only system/task files, writable Agent workspace, cleared environment, resource limits, process-group cancellation, wall timeout, and bounded output; unavailable `bwrap`/`prlimit` fails closed. `AuthorizedHTTPToolAdapter` permits only literal IPs within constructor-supplied CIDRs and ports, disables environment proxies and redirects, bounds methods/headers/body/response/time, and cooperates with cancellation. Neither plugin is registered or authorized by default; Gateway policy still gates each name. Tests run a real sandboxed command, verify workspace/task visibility and rootfs isolation, enforce timeout/output/cancellation, and use a mocked network transport to verify CIDR/port/method checks, redirect refusal, response bounds, Gateway policy denial/allowance, denied-destination status mapping, and untrusted evidence labeling. Gateway now maps adapter authorization refusals to 403 and invalid adapter arguments to 400 without returning exception text. Usage and trust limits are documented in [Gateway tool plugin guidance](../security/gateway-tools.md). Maintainer review is required for these opt-in process/network capabilities.

Validation for the plugin and Gateway error-mapping changes on 2026-10-09: focused plugin/Gateway/adapter/runtime tests passed (31); full suite passed (394 passed, 4 skipped); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Local bubblewrap execution ran; Docker-dependent tests remain skipped in this environment.

**Non-goals:** arbitrary unsandboxed host execution as a default; dynamic tool downloads in offline competition runs.
