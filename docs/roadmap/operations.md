# OPS — Control plane, worker and observability

**Scope:** `api/`, `control_plane.py`, `queue.py`, `worker.py`, `otel.py`, `trace.py`, `telemetry.py`, `audit.py`.

### OPS-01 [~] P2 — Durable job and worker semantics
Deliver: lease and heartbeat recovery, run ownership, cancellation, duplicate dispatch protection and idempotent terminal persistence.
Accept: kill/restart worker, lease expiration and concurrent polling tests; duplicate dispatch never silently repeats unresolved tool effects.

Queue records now have a stable `run_id` (including a migration for existing queue databases). Workers reuse a persisted terminal result for that ID, resume interrupted Pi RPC runs through the existing recovery path, and refuse to repeat an interrupted non-Pi run automatically. Terminal completion/failure writes are idempotent for the same owner and payload. Leases reject heartbeat/complete/fail from an expired owner. Expired jobs move to `reconciliation_required` instead of being silently redispatched; the control-plane token holder can explicitly requeue after reconciling the interrupted run. Worker construction requires authentication, and stale/ambiguous failure reporting does not overwrite another owner's terminal state. Tests cover stable run ownership, legacy database migration, existing-result reuse, safe refusal for interrupted non-Pi runs, expiration, explicit retry, idempotent terminal write, stale owner rejection and concurrent unique claims. A POSIX subprocess test now kills a worker during a real local Agent run, expires its durable lease, confirms the job moves to `reconciliation_required`, and verifies a restarted worker refuses the same run ID without repeating the recorded external effect. Validation on 2026-10-09: full suite passed (303 passed, 3 skipped), Ruff, compileall, architecture test and `git diff --check` passed. Docker/Pi worker kill and resume integration still requires CI evidence.

Added a direct worker regression for interrupted Pi RPC runs: when the stable run directory exists without a terminal result, `_execute` calls Orchestrator with that exact `resume_run_dir` and does not request a new run ID. The targeted worker/queue tests passed (10); latest full suite passed (356 passed, 3 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker-backed worker kill/restart remains unexecuted locally because Docker is unavailable.

Worker heartbeat failure now signals graceful cancellation while the job is executing, allowing Orchestrator to close the Agent and terminate its process group; the stale worker then receives the lease conflict and cannot complete or overwrite the job. This avoids letting an Agent continue producing effects after the worker loses ownership. A POSIX integration test forces heartbeat 409 during a real long-running local Agent, verifies a cancelled run is persisted, the Agent process exits, and no completion request is sent. Heartbeat error details are reduced to the exception class before reporting. Focused worker/queue tests passed (12); full suite passed (371 passed, 3 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker/Pi lease-loss remains unverified locally.

Worker execution exceptions are now reported to the durable control-plane queue as the exception class plus a generic details-omitted marker. Raw provider/container exception text can no longer persist credentials in the queue's failure field. A regression injects a credential-like canary and inspects the exact `/fail` request payload. Worker/queue tests passed (18 passed, 1 Docker test skipped); full suite passed (401 passed, 4 Docker-dependent skips), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker/Pi lease-loss and transport review remain outstanding.

Added a Docker-backed counterpart using the CI Pi RPC probe image. Fake Pi starts a correlated tool call and then hangs; a forced heartbeat 409 must cancel the run, remove the container, retain the pending action in the checkpoint for reconciliation, and avoid a job completion request. Local worker tests passed (7) with the Docker case explicitly skipped; full suite passed (371 passed, 4 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. This extends lease-loss coverage to the container path but requires the CI Docker run before it counts as acceptance evidence.

Terminal job results are now validated at both the HTTP and SQLite queue boundaries: `success` must be boolean, score finite numeric, metrics an object, and leaderboard duration/cost finite and non-negative. Direct queue callers cannot bypass the API checks; invalid completion leaves the lease/job state untouched. The leaderboard ignores malformed legacy result rows rather than failing the whole endpoint. Regressions cover malformed fields, NaN/Infinity, negative metrics, non-mapping metrics and a corrupted legacy row. Queue/control-plane tests passed (27); full suite passed (440 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. The strengthened completion input contract needs maintainer review; Docker/Pi worker lease-loss acceptance remains open.

Worker shutdown no longer races an in-flight heartbeat against job completion. Heartbeat HTTP requests use a bounded timeout shorter than the lease; shutdown marks the heartbeat as stopping, waits a bounded interval for the request thread, and suppresses late lease-loss cancellation callbacks. The worker checks the final heartbeat error after the thread has stopped and refuses to submit completion when that request failed. A deterministic blocked-request/409 regression verifies the thread exits and no late cancellation callback fires. Worker tests passed (14, 1 Docker test skipped); full suite passed (448 passed, 4 skipped), Ruff, compileall, architecture tests (4), and `git diff --check` passed on 2026-10-09. Docker/Pi lease-loss acceptance remains open.

Current-state audit: lease-loss and local signal cancellation are implemented, but there is no control-plane operation for an operator to cancel a queued or running job. Completing this part of OPS-01 requires a new public API and durable queue transitions for cancellation. Per the repository operating contract, stop for maintainer review before changing that public contract; OPS-01 remains in progress.

Concurrent control-plane startup could race the legacy SQLite schema migration: a 12-initializer stress probe failed in 28 of 30 trials with duplicate-column errors for `run_id` or `terminal_owner`. Queue initialization now starts `BEGIN IMMEDIATE` before creating/inspecting/updating the schema, serializing migration decisions across connections. The 12-way legacy-migration regression failed before this change and passes afterward; queue tests passed (14), Ruff and `git diff --check` passed. Operator cancellation still requires public-contract review, and Docker/Pi worker acceptance remains open.

The separate leased-work CoordinationStore allowed an expired owner to heartbeat, complete, fail or release work until another claimant happened to recover the lease. The queue job store already rejects these stale operations. All CoordinationStore owner mutations now require `lease_expires_at > now`; four regression cases failed before the fix and pass afterward, and each verifies that a new owner can reclaim the expired work. Coordination and control-plane tests passed (23), Ruff and `git diff --check` passed. Public operator cancellation and Docker/Pi worker acceptance remain open.

Fresh-database startup stress found the same WAL initialization race in both SQLite stores: CoordinationStore failed once in 30 runs and the job queue failed 5 times in 100 runs with 12 concurrent initializers (`database is locked`). WAL mode is now set only during initialization with bounded retry for transient lock errors; queue DDL/migrations remain inside `BEGIN IMMEDIATE`. New-database concurrency regressions pass, as do 100 rounds of 12 concurrent initializers for each store with zero failures. Queue/coordination tests passed (23), Ruff passed. Multiprocess CI startup evidence remains open.

Lease expiration now uses an inclusive boundary in both stores: at `lease_expires_at == now`, CoordinationStore reclaims the work and SQLiteQueue moves the job to `reconciliation_required`. Both fixed-clock regressions failed before the comparison change and pass afterward. Queue/coordination tests passed (25); full suite passed (493 passed, 4 skipped), Ruff, compileall and `git diff --check` passed on 2026-10-09. Multiprocess CI startup, Docker/Pi worker acceptance and public operator-cancellation review remain open.

### OPS-02 [x] P2 — Trace/provenance contract
Deliver: correlate run/session/action/event/evidence/plan revision; redact credentials/PII and bound output size. Keep trace export independent of internal World DB access.
Accept: JSON schema tests, redaction tests and audit of interrupted run.

`TraceRecorder` emits run/task/event and causal action/plan/subgoal/hypothesis identifiers under the published [trace event schema](../../schemas/trace-event.schema.json). It redacts sensitive-key values, bearer/credential assignments and email addresses; recursively limits depth, collection width and string size, then replaces oversized event data with a hash summary under a 256 KiB event cap. Trace export remains a JSONL-only projection and OTLP export reads that file without opening World storage. Tests cover schema shape, secret/PII redaction, size bounds and audit of an interrupted run. Validation on 2026-10-09: focused trace/audit/OTel tests passed (17); full suite passed (257 passed, 2 Docker tests skipped locally); Ruff, compileall, architecture test, and diff check passed.

Re-audit found top-level trace identifiers (`run_id`, `task_id`, `actor`, event type and causal IDs) bypassed the sanitizer applied to event data, and string assignment redaction omitted `cookie=` and generic `secret=`. All top-level strings now use the same bounded redactor; emitted event IDs return the stored redacted ID so subsequent references remain consistent. A regression covers credential/email canaries in every top-level identity field. Trace tests passed (3); full suite passed (449 passed, 4 skipped), Ruff, compileall, architecture tests (4), and `git diff --check` passed on 2026-10-09.

OTLP conversion and audit JSONL parsing now reject numeric exponents that overflow to non-finite floats (for example `1e999`), in addition to explicit `NaN`/`Infinity` constants.
