# RUN — Runtime, solver and recovery

**Scope:** `solver_loop.py`, `runtime/`, `progress.py`, `session.py`, `orchestrator.py`, `benchmark/runner.py`. Shared bootstrap, lifecycle policies, checkpoints and processed-event ID tracking already exist.

### RUN-01 [x] P0 — Explicit run state machine
Deliver: define allowed transitions among created/running/paused/recovering/verifying/succeeded/failed/exhausted/cancelled; separate pure decision from event normalization and disk/Agent side effects. Use one lifecycle policy for local and benchmark paths.
Accept: table-driven transition tests, illegal transition rejection, exactly one terminal decision, cancellation vs success race tests; no benchmark import in runtime.

Implemented in `runtime.lifecycle.RunLifecycle` and wired into local and benchmark run paths. It models explicit phases and rejects illegal transitions or a second terminal decision; the lifecycle module remains pure and has no benchmark imports. Tests cover valid transition edges, invalid transitions, terminal immutability, and both cancellation/success orderings. Local and benchmark paths enter `running`, enter `verifying` before final objective evaluation, and settle to one internal terminal phase. See [lifecycle tests](../../tests/test_runtime_lifecycle.py). Validation on 2026-10-09: full suite passed (192 passed, 1 Docker integration skipped); Ruff and architecture checks passed. Maintainer review is required before merge with the related trust-boundary changes.

### RUN-02 [~] P0 — Crash-safe checkpoints and action reconciliation
Deliver: durable agent cursor, World revision, budget, feedback cursor and in-flight action IDs; recovery protocol for action dispatch/effect/feedback/checkpoint crash windows. Already available file checkpoints and explicit operator reconciliation are a base, **not** exactly-once crash resume.
Accept: fault-injection tests across every boundary; unknown effect never automatically retried; mismatch and corrupt checkpoint detected; no double billing/events on duplicate ingestion.

Extended checkpoint writes to each consumed session event in both local and benchmark streams, retaining the agent cursor, feedback cursor, World revision, plan revision, processed event identities, active tool calls, and live usage metrics before advancing. The one-shot adapter now advances its cursor only through the event it yielded, even when the backing file already contains later events. Atomic replacement fsyncs both the checkpoint file and its parent directory. Uncorrelated legacy in-flight actions are persisted. Explicit reconciliation now leaves `unknown` actions pending and blocks recovery; an operator must later resolve them as succeeded or failed before recovery can proceed. The stream-crash regression proves a dispatched action remains pending and `load_recovery_state` refuses to resume until explicit reconciliation. Tests cover per-event cursor ordering, atomic file and directory durability, replacement failure, stale World revision, run ID mismatch, corrupt checkpoint data, parallel active actions, idempotent reconciliation retry, duplicate event ingestion, and unknown outcomes. Initial validation on 2026-10-09: checkpoint tests passed (22); full suite passed (205 passed, 1 Docker integration skipped). At that point, end-to-end session restore and the broader fault matrix remained open. No exactly-once resume claim is made.

Added a baseline checkpoint immediately after session startup in both local and benchmark session loops, before steering or prompting the Agent. Added an opt-in `--resume-run` / `Orchestrator.run(resume_run_dir=...)` path for interrupted Pi RPC runs. It verifies the run is a direct, non-symlink child of the configured runs root, rejects terminal or mismatched task/Agent inputs, restores the existing World and Progress ledger, checks the checkpoint's World revision and action state, and passes the persisted Pi session ID back to the adapter. Pi RPC startup now waits for and validates its session identity before the baseline checkpoint and before prompting the Agent. Recovery refuses when the Progress ledger contains an active action or its event count/identity is ahead of its checkpoint; it carries cumulative usage into results and reduces all configured budgets by prior use and elapsed wall time. Resume is refused for reconciled action history because a restored model transcript could repeat a side effect; Pi event identities include a fresh process epoch. Existing Docker Compose services are resumed with `start` and never rebuilt; a still-running Pi container blocks resume. An interrupted resume keeps the workspace/checkpoint and avoids writing a terminal result, while closing the session and stopping the environment without removing its state. Fault-injection coverage now exercises failure after dispatch, after effect but before checkpoint, after feedback but before checkpoint, and stream failure after a durable checkpoint; stale Progress/World, unresolved actions, bad IDs, and corrupted checkpoints all fail closed. Added a fake Pi RPC image and Docker-backed resume integration test to CI; the local test skips because Docker is unavailable. See [checkpoint tests](../../tests/test_checkpoint.py), [benchmark streaming/recovery tests](../../tests/test_benchmark_streaming.py), [smoke/recovery tests](../../tests/test_smoke.py), [Docker Pi resume test](../../tests/test_pi_resume_docker.py), [environment tests](../../tests/test_environment.py), and [Pi adapter tests](../../tests/test_pi_adapter.py). Validation on 2026-10-09: `ruff check .`, `pytest -q` (235 passed, 2 Docker tests skipped), `python -m compileall -q src tests`, and `git diff --check` passed. This remains in progress until Docker-backed CI evidence is available; the checkpoint protocol is not an exactly-once guarantee.

Progress ledger writes are now durable atomic replacements as well: each `progress.json` update is written to a same-directory temporary file, fsynced, atomically renamed, and followed by a directory fsync before the caller advances its checkpoint. A replacement-failure injection proves the prior ledger remains parseable and unchanged. Validation on 2026-10-09: full suite passed (285 passed, 3 Docker-dependent skips); Ruff, compileall, architecture check, and diff checks passed. Full recovery acceptance still depends on Docker CI fault runs.

Operator reconciliation reports now use no-follow reads and atomic, fsynced replacement. This prevents a symlinked `action.reconciliation.json` from being trusted as a prior reconciliation record or redirecting report writes. Reconciliation retries remain idempotent if report persistence fails after Progress and checkpoint updates. Regression coverage includes a valid forged report through a symlink and injected report-write failure. Validation on 2026-10-09: checkpoint tests passed (28); full suite passed (334 passed, 3 skipped), Ruff, compileall, architecture test and `git diff --check` passed. The Docker Pi recovery fault matrix remains required for final acceptance.

Legacy `tool.call` events without a `tool_call_id` now receive a stable action ID derived from their persisted event ID. A matching ID-less `tool.result` is correlated only when there is exactly one active action with the same tool; ambiguous parallel results remain unresolved and block resume. Event-to-action mappings persist in `progress.json`, so replay after restoring the ledger produces the same correlation and duplicate event identity is still rejected. Regression coverage restores the ledger between dispatch and result, verifies consistent World action IDs, replays the original dispatch without adding a tool call, and leaves multiple same-tool actions unresolved when the result cannot be uniquely correlated. Validation on 2026-10-09: focused solver/checkpoint/session tests passed (51); latest full suite passed (345 passed, 3 skipped); Ruff, compileall, architecture test (1 passed), and `git diff --check` passed. Docker Pi recovery fault-matrix evidence and the existing no-exactly-once limitation remain outstanding.

Checkpoint parsing now rejects boolean and string values in `budget_used` before numeric coercion; otherwise `true` could be restored as one unit of usage and numeric strings could silently alter recovery budgets. Fixed the invalid-checkpoint test fixture to include the required feedback cursor so each corruption case is actually exercised. Focused checkpoint tests passed (30); full suite passed (367 passed, 3 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker Pi recovery fault-matrix evidence and the no-exactly-once limitation remain outstanding.

Action reconciliation now takes a per-run cross-process exclusive lock before reading or writing checkpoint, progress and the operator report. This prevents two concurrent maintainers from applying opposing outcomes based on the same stale state and leaving the three durable records inconsistent. The lock is opened as a no-follow regular file and unsupported safe-locking platforms fail closed. A deterministic threaded race holds the first reconciler after checkpoint load, confirms the second cannot read stale state, then verifies its conflicting outcome is rejected and all persisted records agree. Checkpoint/smoke/benchmark recovery tests passed (62); full suite passed (404 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker recovery CI evidence remains open.

Also made checkpoint usage counters preserve integer values and reject fractional token/call counts before recovery converts them to integers. Corrupt values such as `total_tokens=3.5` can no longer be truncated to 3 and undercount prior use. Checkpoint tests cover booleans, strings, integral/fractional float counters, negatives and non-finite values. Focused checkpoint tests passed (32); full suite passed (370 passed, 3 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker Pi recovery fault-matrix evidence and the no-exactly-once limitation remain outstanding.

Resume wall-time accounting now rounds elapsed fractional seconds up before subtracting from the task budget. A run resumed after 3.1 seconds of a 10-second budget therefore receives 6 seconds, not 7. The regression failed before the change and passes after it, alongside the existing cumulative usage resume test. Full suite passed (368 passed, 3 skipped), Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker Pi recovery fault-matrix evidence and the no-exactly-once limitation remain outstanding.

### RUN-03 [x] P1 — Event processing and bounded autonomy
Deliver: dedupe with persisted identity, stable ordering and world-event revisions; explicit continue/verify/replan/stop decisions; bounded replan frequency and budget/time thresholds.
Accept: duplicate/reordered event tests, no progress loops terminate appropriately, goal verification dominates generic completion, reproducible trace transitions.

`solver_policy.decide_solver_action` now provides pure continue/verify/replan/stop decisions. The loop persists plan counts, records each decision in `solver.decision` trace events, caps replans at eight, stops after six no-progress outcomes, and stops with exhausted budgets or at 5% remaining budget when no progress continues. Duplicate IDs and conflicting payloads remain distinct audit outcomes. The World-order regression delivers out-of-order lexically named IDs and verifies stream-arrival order determines revision order while replaying an identical event does not add a revision. Orchestrator integration confirms the Agent session closes at the stop bound and an independent objective verifier can still accept evidence produced before stopping. See [solver policy tests](../../tests/test_solver_policy.py), [solver loop tests](../../tests/test_solver_loop.py), and [smoke tests](../../tests/test_smoke.py). ### RUN-04 [~] P2 — Resource ownership
Deliver: one owner for container/session/gateway/task teardown, consistent timeouts and cancellation, terminal persistence idempotency.
Accept: forced kill, signal interruption and external benchmark teardown tests; no leaked resources or overwritten terminal results.

Shared terminal result persistence now writes and fsyncs a temporary file, atomically publishes it without replacing an existing result, treats byte-identical retries as idempotent, and rejects conflicting terminal payloads. `SIGINT`/`SIGTERM` in the local Orchestrator now enter a cancelled terminal result after run-owned session, Gateway, and environment cleanup. One-shot CLI/Docker execution polls its session close control file and terminates the spawned process group; Pi container sessions retain explicit container termination. Tests run an actual long-lived CLI subprocess and verify both explicit session close and a real SIGTERM leave no Agent process, while SIGTERM persists `cancelled` and `run.finished`. Regression coverage is in [runtime signal tests](../../tests/test_runtime_signals.py), [session tests](../../tests/test_session_telemetry.py), and [runtime result tests](../../tests/test_runtime_results.py). Forced SIGKILL recovery and Docker/external benchmark teardown still need integration evidence; the item remains in progress.

Linux host CLI runs now launch through a small parent-death supervisor. It uses `PR_SET_PDEATHSIG`, starts the Agent in a private process group, forwards shutdown to the whole group, and cleans up Agent subprocesses when the Agent exits. A subprocess regression sends SIGKILL to the Orchestrator and verifies both the Agent and its spawned child exit, the durable checkpoint remains, and no terminal result is written. The SIGTERM cancellation regression also verifies descendant cleanup. A direct process-guard test confirms child processes are reaped after a normal Agent exit. The generic benchmark runner cancellation contract test verifies it closes the Agent session with a cancellation reason and always tears down the benchmark adapter. Focused runtime signal/process-guard tests passed (3); benchmark streaming tests passed (14). Latest validation on 2026-10-09: full suite passed (345 passed, 3 skipped); Ruff, compileall, architecture test (1 passed), and `git diff --check` passed. Docker container and live external benchmark teardown remain unverified, so RUN-04 stays in progress.

Benchmark runner review found teardown was not entered for failures between a successful external `provision()` and the agent loop, including solver bootstrap failures; an unsupported container network was also checked only after allocating the external session. That network compatibility check now runs before run allocation/provision. A single idempotent teardown owner now covers all post-provision setup failures as well as normal execution and cancellation. Fault injection verifies a bootstrap failure closes the provisioned adapter exactly once, while the invalid-network test verifies no session is provisioned. Focused benchmark lifecycle tests passed (4); full-suite validation pending. External TSec/Docker teardown remains environment-dependent.

Validation on 2026-10-09: benchmark streaming/lifecycle tests passed (16); full suite passed (396 passed, 4 skipped); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed. Docker and live external benchmark teardown remain unverified.

Local run cleanup now attempts Gateway and Environment shutdown before writing any cleanup-error trace. A trace filesystem failure while reporting a Gateway stop error can no longer skip Environment teardown; the unrecordable failure class is sent to the standard logger without exception text. A regression injects both a Gateway stop failure and a failure to append its trace event, then verifies Environment stop still occurs and terminal result persistence completes. Focused smoke/signal/result/benchmark lifecycle tests passed (37); full suite passed (413 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Docker/external teardown remains unverified.

Benchmark provision and teardown errors now persist only the exception class and a generic details-omitted message. Previously raw external adapter exception text was written to the trace and terminal cleanup result, where provider or benchmark credentials could leak. Canary regressions failed before the fix and pass after it. Benchmark streaming tests passed (20); full suite passed (444 passed, 4 skipped), Ruff, compileall, architecture tests (4), and `git diff --check` passed on 2026-10-09. This closes the artifact-redaction gap but does not replace Docker/external benchmark teardown acceptance.

Benchmark teardown now runs in one shielded task with a 30-second bound. If the runner is cancelled while the external adapter is cleaning up, it waits for teardown to complete before propagating cancellation; this avoids interrupting resource release after the one-shot teardown guard has been set. If teardown stalls, the task is cancelled and a safe timeout error is persisted so the run can converge. Regressions verify cancellation waits for cleanup and that a stuck adapter is cancelled and reported without hanging. Benchmark streaming tests passed (23); full suite passed (447 passed, 4 skipped), Ruff, compileall, architecture tests (4), and `git diff --check` passed on 2026-10-09. Docker and live external benchmark teardown acceptance remains open.

Checkpoint payloads now have a shared 8 MiB read/write limit, and save rejects an over-limit record before replacing the last readable checkpoint. Session checkpointing trims older processed-event identities to preserve the newest identities, while the live solver cache is capped at 50,000 entries to avoid repeatedly serializing an oversized map on every subsequent event. Regressions verify oversized writes preserve the previous file and that a large identity map is trimmed to a loadable checkpoint retaining its newest event. Focused checkpoint/solver tests passed (45); full suite passed (415 passed, 4 Docker-dependent skips); Ruff, compileall, architecture tests (2 passed), and `git diff --check` passed on 2026-10-09. Docker-backed recovery fault-matrix evidence remains outstanding; RUN-02 remains in progress.

Recovery now takes the same per-run cross-process lock as operator reconciliation while reading `checkpoint.json` and `progress.json`. This prevents recovery from observing the interval after one durable record changes but before the other and the reconciliation report are published. A deterministic threaded regression pauses reconciliation after the progress write and confirms recovery blocks until all records agree. Checkpoint tests passed (36); full suite passed (452 passed, 4 Docker-dependent skips), Ruff, compileall and `git diff --check` passed on 2026-10-09. Docker-backed recovery fault-matrix evidence remains open.

Operator reconciliation now refuses any run directory that already contains `result.json`, checking with `lstat` so even a dangling or linked terminal marker cannot be ignored. This prevents a late operator call from rewriting checkpoint/progress after terminal result publication. The regression confirms the refusal leaves both records byte-identical and creates no reconciliation report. Focused checkpoint tests passed (2); Ruff and `git diff --check` passed. This protects finalized runs; live-run exclusion and Docker-backed recovery fault-matrix evidence remain open.

Local Orchestrator and benchmark Agent execution now hold a per-run cross-process action-owner lock for the full Agent session/run call. Operator reconciliation must acquire that same no-follow lock before the reconciliation mutation lock, so it refuses while an Agent or another reconciler owns the run and cannot rewrite a live pending-action record. A threaded regression confirms refusal leaves checkpoint and progress byte-identical; the existing conflicting-operator race remains serialized. Checkpoint/runtime-profile/benchmark-streaming tests passed (65); Ruff and `git diff --check` passed. Docker recovery fault-matrix evidence remains outstanding.

The benchmark runner now releases the provisioned service if action-owner lock acquisition fails; its cleanup path releases the lock only after successful acquisition. A fault-injection regression confirms teardown still runs exactly once. Benchmark streaming, checkpoint and architecture tests passed (64); Ruff and `git diff --check` passed. External benchmark teardown evidence remains open.
